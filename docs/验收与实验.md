当前均为 Row，LTR，crossAxisAlignment.center，三个色块各 36。设 Row 宽 W，剩余空间 F=W−108：

| 参数 | 第一个块前方空白 | 相邻块间空白 |
| --- | --- | --- |
| start | 0 | 0 |
| end | F | 0 |
| center | F/2 | 0 |
| spaceBetween | 0 | F/2 |
| spaceAround | F/6 | F/3 |

以上位置已用几何测试验证。**这是六种标准主轴对齐，不自动等同于课堂任务卡**；如果原题含 Column、交叉轴或 baseline，需要按原题调整后再提交。

## 3. 弹性分配

三个 Expanded 的 flex 为 2、1、1，Row 中没有另加占宽的间隔组件。因此内容可用宽 W 分成 W/2、W/4、W/4。各栏内部 padding 不另外扩大总宽。

操作：进入“弹性”→短文→打开长文→选择省略。

- 换成长文：列宽保持比例，文字在第一栏的有限宽度内换行。
- 换行模式：文字可能增高；卡片所在页面允许竖向滚动。
- 省略模式：maxLines:1 与 overflow:TextOverflow.ellipsis 配合，显示不下的部分不再展开。
- 自动测试确认宽度比例、长文不改变列宽、无框架异常、单行省略配置；实际文字行数随字体与视口变化，不写死。

本人补充：视口宽【待填】，三列 Inspector 实际宽【待填】，长文前后现象【待填】。

## 4. 溢出定位（必做调试证据用）

运行 `flutter run -d chrome -t lib/overflow_demo.dart`。关闭“使用 Expanded 修复”：Row 宽 240，三个子项各请求宽 120，总共 360，超出 120。打开开关后：Expanded 给每个子项宽 80 的紧约束，原先请求的 width:120 必须服从父级约束。

自动测试已实际捕获 `overflowed by 120 pixels`，修复后验证三项宽 80、无异常。此测试是刻意捕获预期错误，不代表主程序有溢出。

本人要补：Inspector 选择 Row 及子项时的 constraints、size，修前与修后截图。**自动测试读取 RenderBox 尺寸不是本人 Inspector 检查。**

教师另要求临时去掉名片统计条 Expanded，再加回。短标签可能只是聚拢而不溢出；如实记录观察，不能写成“删 Expanded 必然溢出”。做完恢复原文件，再运行测试。

## 5. 已遇到的另一个真实问题

初次测试中 SwitchListTile 报错：`ListTile background color or ink splashes may be invisible.` 原因是最近的 Material 在白色装饰 Container 外面，背景装饰会遮住墨水绘制。StudyCard 在 decoration 内新增透明 Material，原先失败的测试恢复通过。失败日志在 `evidence/debug-material-before.txt`，成功日志在 `evidence/flutter-test.txt`。此调试由 Codex 执行；不替代第 4 节的本人 Inspector 实验。

## 6. 材料中容易误读的地方

- Wrap 的参数是 `alignment` 和 `runAlignment`，不存在 `wrapAlignment`。
- BoxFit.cover 决定图片如何填充已分配区域，不负责替 Stack 创造外层尺寸。本项目用 SizedBox 明确高度 200。
- Expanded 用于 Flex/Row/Column 的相应布局位置，且要考虑主轴是否有界，不能随便套在任意组件外。
- Container 不能同时传 color 与 decoration；这由构造断言检查，不是所有情况下都表现成编译期类型错误。
- 圆角装饰不自动剪裁子组件；图片另用 ClipRRect。
